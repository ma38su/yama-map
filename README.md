# やまマップ（yama-map）

山歩き用の地図アプリ（PWA）。スマホのブラウザで開いて、メニューの「ホーム画面に追加」からインストールすればアプリのように使えます。
画面を消したまま記録したいときは Android アプリ版も作れます（[Androidアプリ](#androidアプリcapacitor)）。

> この地図は登山計画の参考です。紙の地図とコンパス、登山届の提出もお忘れなく。

## できること

### 地図
- 国土地理院の地図（標準地図／淡色地図／航空写真）と陰影起伏
- **2D / 3D 切り替え**：標高タイルで地形を立体表示。3D では **1本指で回転・傾き、2本指で移動**（ピンチで拡大縮小）
- **時刻に合わせた空と地図の色**：太陽の位置から空の色と陰影の向きを計算。夕方は暖色、夜は暗めの青（地図は読める明るさを保つ）。メニューでオフにできる
- **天気予報**：3D では予報の雲量に合わせて地形に雲がかかり、雨・雪の予報では画面に雨粒・雪を降らせる。曇りの予報では空も灰色に寄せる（[Open-Meteo](https://open-meteo.com/)、メニューでオフにできる）
- 現在地（GPS）の表示と追従
- **オフライン保存**：表示範囲の地図・標高・道データを端末に保存（山の中の圏外対策）

### ルートと到着予想
- 地図をタップ →「出発地 / 経由地 / 目的地」で、**道・登山道沿いのルートを自動作成**（地名も自動で付く）
- ルートの探し方はメニューの設定で「登山道優先」（初期値）か「最短距離」。ルート沿いの温泉・小屋・山頂・滝などは通過点として自動で追加
- **到着予想時刻**：下のバーに次の地点と目的地の「◯時◯分着・あと◯分」、日没との比較
- **天気**：行程の各地点に、到着予想の時刻の天気・降水確率・気温を表示。バーには、これから通る地点の降水確率のうち最大のものを出す
- **出発時刻**：「今すぐ」と時刻欄を並べて表示。時刻を変えると、その時刻に出発した場合の予想になる。記録を始めると「今すぐ」に戻る
- GPX ルートの読み込み・書き出し、おすすめルート（女夫渕 → 手白澤温泉）

### 記録
- **GPS で軌跡を記録**（距離・時間・累積標高）→ 端末に保存、GPX で書き出し
- 記録中は歩いた実績（登り・平坦・下りの速さ、休憩の取り方）から到着予想を自動で調整
- **保存した記録を開くと実績を表示**：
  - バー上部に出発と目的地の時刻、行程に通過した地点・休憩・到着の時刻と区間ごとの所要時間を出す
  - 開いているあいだは記録開始ボタンの代わりに「リプレイ」と「閉じる」を出し、現在地の表示はオフ
- **3D リプレイ**：時間を縮めて歩いた位置を動かし、カメラが進む向きに追いかける（×100 / ×300 / ×1000、休憩は速送り、スライダーで位置を移動）。空と地図の色、雲と雨も再生中の時刻に合わせる。操作バーの ● で**リプレイを録画**し、webm の動画として保存できる（字幕に記録の名前と時刻）
- 最初から「予定」の記録が1件入っている：おすすめルートを今日の11:30から、ゆっくりのペースで歩き、30分ごとに5分休む想定。記録の見え方を試せる

### 下のパネル
バーを引き上げると詳細が見られます（半分・全画面の2段階。全画面では地図が隠れる）。

- **行程**タブ：出発時刻、地点ごとの到着予想（記録を開いているときは実績）、区間の距離・登り下り・時間
- **標高・ペース**タブ：
  - 標高グラフ：横軸を距離と時刻で切り替え、ピンチ・ボタンで横に拡大
  - 記録のグラフ：区間ごとのペース（遅いほど赤、速いほど青）と休憩を表示
  - これまでのペース：経過・歩行・休憩時間、平均速度、登りの速さ、標準タイム比

画面はスマホ縦持ち（Pixel 8a 412×915 を基準）向け。操作は親指の届く下側に集めています。

## 到着予想の考え方

1. **標準タイム**：経路を50mごとに区切り、距離と勾配から Tobler のハイキング関数×0.8 で歩行時間を求める（平地 約4km/h、急な登り・下りで遅くなる）。
   女夫渕→八丁の湯 1:09、→加仁湯 0:11、→手白澤温泉 0:34 と、公表コースタイム（70分・10分・40分）とほぼ一致。
2. **あなたのペース**：記録した軌跡から「登り・平坦・下り」それぞれで標準の何倍かかっているかを求め、残りの区間に当てはめる。記録が少ないうちは設定（ゆっくり 1.25倍／ふつう／速め 0.85倍）に寄せる。
3. **休憩**：90秒以上ほとんど進んでいない区間を休憩として検出し、歩行1時間あたりの休憩時間を求めて残りの行程に上乗せ（記録が少ないうちは1時間あたり10分を見込む）。
4. **日没**：到着予想が日没30分前を過ぎると赤く表示。

## 開発

```bash
npm install
npm run dev      # 開発サーバー http://localhost:3030
npm run serve    # 本番ビルドを http://localhost:3030 で配信（Service Worker・オフライン対応込み）
npm test         # ユニットテスト（vitest）
npm run build    # 型チェックして dist/ に出力
```

- ポート3030は Cloudflare Tunnel などでスマホから開く想定で、外部ホスト名からのアクセスを許可しています（`vite.config.ts`）
- URL に `?time=18:30` を付けると、その時刻の空と地図の色を確かめられます
- 動作確認用に `window.yamaMap`（地図・記録・到着予想・ルート）をコンソールから触れます

コードの構成と仕組みは [docs/architecture.md](docs/architecture.md)、PWA かネイティブか・電池持ち・地図データの検討は [docs/design-notes.md](docs/design-notes.md)、Android アプリ版の作り方は [docs/android.md](docs/android.md) にまとめています。

### 公開（GitHub Pages）

GPS（位置情報）は **HTTPS でないと動きません**。スマホで試すには GitHub Pages に置くのが手軽です。

1. リポジトリの Settings → Pages → Source を **GitHub Actions** にする
2. `main` ブランチに push すると `.github/workflows/ci.yml` が型チェック・テスト・ビルドをして `https://<ユーザー名>.github.io/yama-map/` に公開
3. スマホでそのURLを開き、メニューの「ホーム画面に追加」からインストール（iPhone・iPad は Safari の共有ボタン →「ホーム画面に追加」）

### Androidアプリ（Capacitor）

画面を消したままでも記録できる Android アプリ版を作れます。中身は PWA と同じコードで、
記録の測位だけがネイティブのバックグラウンド測位（記録中は通知が出ます）に切り替わります（`src/track/location.ts`）。

必要なもの：JDK 21（`brew install openjdk@21`）と Android SDK（`android/local.properties` の `sdk.dir` で場所を指定。このファイルはコミットしない）

```bash
export JAVA_HOME=/opt/homebrew/opt/openjdk@21/libexec/openjdk.jdk/Contents/Home
npm run android:build   # dist/ を取り込んで android/app/build/outputs/apk/debug/app-debug.apk を作る
adb install -r android/app/build/outputs/apk/debug/app-debug.apk
```

家族などに配るときは APK ファイルを送り、受け取った端末で「提供元不明のアプリ」のインストールを許可してもらいます。
初回の記録開始時に「位置情報」と「通知」の許可を求めます。電池の最適化でアプリが止められる端末では、
設定でやまマップを「制限なし」にすると記録が途切れにくくなります。

Web版との違い、ビルド環境の準備、エミュレータ、デバッグ、署名とアップデートの注意は [docs/android.md](docs/android.md) にまとめています。
