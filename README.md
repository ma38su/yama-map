# やまマップ（yama-map）

山歩き用の地図アプリ（PWA）。スマホのブラウザで開いて、メニューの「ホーム画面に追加」からインストールすればアプリのように使えます。
画面を消したまま記録したいときは Android アプリ版も作れます（[Androidアプリ](#androidアプリcapacitor)）。

> この地図は登山計画の参考です。紙の地図とコンパス、登山届の提出もお忘れなく。

## できること

### 地図
- 国土地理院の地図（標準地図／淡色地図／航空写真）と陰影起伏
- **2D / 3D 切り替え**：標高タイルで地形を立体表示。3D では **1本指で回転・傾き、2本指で移動**（ピンチで拡大縮小）。起伏の強調はメニューで変えられる
- **時刻に合わせた空と地図の色**：太陽の位置から空の色と陰影の向きを計算。夕方は暖色、夜は暗めの青（地図は読める明るさを保つ）。メニューでオフにできる
- **天気予報**：3D では予報の雲量に合わせて地形に雲がかかり、予報で雨・雪が降っている場所にだけ雨粒・雪を降らせる。曇りの予報では空も灰色に寄せる（[Open-Meteo](https://open-meteo.com/)。予報の表示と、雲・雨のアニメーションは、メニューでそれぞれオフにできる）
- 現在地（GPS）の表示と追従。現在地の印に向いている方向の扇を出し、「進む向きを上」にすると向きに合わせて地図を回す（方位センサー、なければ GPS の進行方向）
- **地名の検索**：山・沢・温泉などの名前で探し、選ぶとその場所の吹き出し（出発地・経由地・目的地）を出す（国土地理院の地名検索）
- **山小屋・水場・写真などを地図に重ねる**：種類ごとに色とアイコンの違う吹き出しで出し、タップで詳しく見る（その場所を出発地・目的地にもできる）。地図の右上の「重ねる情報」ボタンで、種類ごとに表示・非表示を切り替えられる
  - 山の施設（山小屋・避難小屋・水場・トイレ・キャンプ場・展望地・温泉・滝）：[OpenStreetMap](https://www.openstreetmap.org/)（Overpass API。混んでいて取れないときは、端末に残っている OpenFreeMap の地図データから名前と種類だけ）
  - 写真：[Wikimedia Commons](https://commons.wikimedia.org/) の位置付きの写真、生きもの：[iNaturalist](https://www.inaturalist.org/) の写真付きの観察記録（どちらも自由なライセンスのものだけ。撮影者とライセンスを表示）
  - **自分の場所のファイル**（GeoJSON の点・GPX のウェイポイント）を読み込んで、コメントや写真付きで出せる（形式は [docs/places.md](docs/places.md)）
  - 一度見た場所は端末に残り、圏外でも出る
- **オフライン保存**：**ルート沿い**（ルートの両側 500m・1km・2km の帯）か表示中の範囲の地図・標高・道データを端末に保存（山の中の圏外対策）。山小屋・水場などの情報と写真（縮小画像）も一緒に保存する。
  保存した範囲は、メニューの一覧（地図で見る・範囲ごとに削除）と、地図の緑の塗り（「重ねる情報」→「保存した範囲」）で確かめられる

### ルートと到着予想
- 地図をタップ →「出発地 / 経由地 / 目的地」で、**道・登山道沿いのルートを自動作成**（地名も自動で付く）
- ルートの探し方はメニューの設定で「登山道優先」（初期値）か「最短距離」。ルート沿いの温泉・小屋・山頂・滝などは通過点として自動で追加
- **到着予想時刻**：下のバーに次の地点と目的地の「◯時◯分着・あと◯分」、日没との比較
- **天気**：行程の各地点に、到着予想の時刻の天気・降水確率・気温を表示。バーには、これから通る地点の降水確率のうち最大のものを出す
- **出発時刻**：「今すぐ」と時刻欄を並べて表示。時刻を変えると、その時刻に出発した場合の予想になる（今より6時間以上前の時刻は明日の出発とみなす。夜に翌朝の時刻を入れたとき）。記録を始めると「今すぐ」に戻る
- GPX ルートの読み込み・書き出し、おすすめルート（女夫渕 → 手白澤温泉、女夫渕 → 日光澤温泉）

### 記録
- **GPS で軌跡を記録**（距離・時間・累積標高）→ 端末に保存、GPX で書き出し
- 記録中は歩いた実績（登り・平坦・下りの速さ、休憩の取り方）から到着予想を自動で調整
- 記録中の地図：歩いた軌跡は太い赤、これからのルートは青に進む向きの白い矢印、歩き終えた部分のルートは灰色。通った地点は薄く、次に向かう地点は青い輪で示す。カードには出発地〜目的地のどこにいるかの棒（シートを最小にしても出る）
- **道迷いアラート**：記録中にルートから離れたら、振動と通知で知らせる（アプリ版は画面を消していても。メニューでオフにできる）
- **写真**：記録中にカメラで撮る・あとから写真を選ぶと、撮った場所（写真の位置情報、なければ撮った時刻と軌跡）に置いて地図に出す
- アプリ版で気圧計がある端末は、**気圧の変化で標高を補う**（標高タイルだけより、登り下りが正確になる）
- **ポケット表示**：記録中に下のバーの 🌙 を押すと、黒い画面に時刻・経過・距離・次の地点と目的地の到着予想・日没だけを大きく出し、地図の描画を止める（画面を点けたままでも電池の減りを抑える）。
  ポケットの中で触れても戻らないよう、地図に戻るのは「長押しで地図に戻る」を1秒押したとき・戻るボタン（アプリ版）・記録を終えたとき
- ポケット表示には、**ペース**（標準タイムと比べて速い・遅い。直近20分と記録全体）も出す
- アプリ版は、記録を始めたときに一度だけ「電池の最適化から外すか」を聞く（メニューの「記録」でも状態の確認と設定ができる）
- **記録を別の端末へ移す**：メニューの「記録をまとめて書き出す」で、すべての記録（写真も）を1つのファイルにし、もう一方の端末（Pixel 8a と 9 Pro など）の「記録を読み込む」で取り込む。バックアップにもなる
- **動作の記録**：メニューから、端末の状態とアプリの動き（エラー、10分ごとの電池・測位などの計測）をまとめて見て、ファイルで送れる（USB でつながなくても不具合やパフォーマンスを調べられる。位置は伏せる）
- **保存した記録を開くと実績を表示**：
  - バー上部に出発と目的地の時刻、行程に通過した地点・休憩・到着の時刻と区間ごとの所要時間を出す
  - 開いているあいだは記録開始ボタンの代わりに「リプレイ」と「閉じる」を出し、現在地の表示はオフ
- **3D リプレイ**：時間を縮めて歩いた位置を動かし、カメラが進む向きに追いかける（×100 / ×300 / ×1000、休憩は速送り、スライダーで位置を移動）。空と地図の色、雲と雨も再生中の時刻に合わせる。操作バーの ● で**リプレイを録画**し、webm の動画として保存できる（字幕に記録の名前と時刻）
- 最初から「予定」の記録が1件入っている：おすすめルートを今日の11:30から、ゆっくりのペースで歩き、30分ごとに5分休む想定。記録の見え方を試せる

### 下のパネル
バーを引き上げると詳細が見られます（半分・全画面の2段階。全画面では地図が隠れる）。

- **行程**タブ：出発時刻、地点ごとの到着予想（記録を開いているときは実績）、区間の距離・登り下り・時間。歩いている途中は「現在地」の行（歩いた距離・残り・次の地点まで）を通った地点と次の地点のあいだに入れ、開くとその行まで送る
- **標高・ペース**タブ：
  - 標高グラフ：横軸を距離と時刻で切り替え、ピンチ・ボタンで横に拡大。歩いている途中は今の位置に縦線と「現在地」の札を出し、歩き終えた部分を灰色にする
  - 記録のグラフ：区間ごとのペース（遅いほど赤、速いほど青）と休憩を表示
  - これまでのペース：経過・歩行・休憩時間、平均速度、登りの速さ、標準タイム比

画面はスマホ縦持ち（Pixel 8a 412×915 を基準）向け。操作は親指の届く下側に集めています。
下のシートはカードを上下にドラッグして、最小（目的地の1行だけ。地図・3Dを広く見る）／閉じる／半分／全画面の4段に切り替えます。最小にするには、閉じた状態からさらに下へ引きます。タップすると元に戻ります。

## 到着予想の考え方

1. **標準タイム**：経路を50mごとに区切り、距離と勾配から Tobler のハイキング関数×0.8 で歩行時間を求める（平地 約4km/h、急な登り・下りで遅くなる）。
   女夫渕→八丁の湯 1:09、→加仁湯 0:11、→手白澤温泉 0:34 と、公表コースタイム（70分・10分・40分）とほぼ一致。
2. **あなたのペース**：記録した軌跡から「登り・平坦・下り」それぞれで標準の何倍かかっているかを求め、残りの区間に当てはめる。記録が少ないうちは設定（ゆっくり 1.25倍／ふつう／速め 0.85倍）に寄せる。
3. **休憩**：90秒以上ほとんど進んでいない区間を休憩として検出し、歩行1時間あたりの休憩時間を求めて残りの行程に上乗せ（記録が少ないうちは1時間あたり10分を見込む）。
4. **記録中の現在地**：今の時刻と、現在地をルートに当てはめた位置から先を計算する。ルートから300m以上離れたら、いちばん近いルート上の地点まで平坦な直線で戻る時間を足し、そこから先を計算する（5km以上離れているときは出発地から）。
5. **日没**：到着予想が日没30分前を過ぎると赤く表示。

## 開発

```bash
npm install
npm run dev      # 開発サーバー http://localhost:3030
npm run serve    # 本番ビルドを http://localhost:3030 で配信（Service Worker・オフライン対応込み）
npm test         # ユニットテスト（vitest）
npm run build    # 型チェックして dist/ に出力
```

- ポート3030は Cloudflare Tunnel などでスマホから開く想定で、外部ホスト名からのアクセスを許可しています（`vite.config.ts`）
- URL に `?time=18:30` を付けると、その時刻の空と地図の色を確かめられます
- 動作確認用に `window.yamaMap`（地図・記録・到着予想・ルート）をコンソールから触れます

コードの構成と仕組みは [docs/architecture.md](docs/architecture.md)、PWA かネイティブか・電池持ち・地図データの検討は [docs/design-notes.md](docs/design-notes.md)、Android アプリ版の作り方は [docs/android.md](docs/android.md)、常駐アプリとして使うための改善計画は [docs/android-plan.md](docs/android-plan.md) にまとめています。

### 公開（GitHub Pages）

GPS（位置情報）は **HTTPS でないと動きません**。スマホで試すには GitHub Pages に置くのが手軽です。

1. リポジトリの Settings → Pages → Source を **GitHub Actions** にする
2. `main` ブランチに push すると `.github/workflows/ci.yml` が型チェック・テスト・ビルドをして `https://<ユーザー名>.github.io/yama-map/` に公開
3. スマホでそのURLを開き、メニューの「ホーム画面に追加」からインストール（iPhone・iPad は Safari の共有ボタン →「ホーム画面に追加」）

### Androidアプリ（Capacitor）

画面を消したままでも記録できる Android アプリ版を作れます。中身は PWA と同じコードで、
記録の測位だけが、アプリの中のフォアグラウンドサービス（記録中は通知が出ます）に切り替わります（`src/track/location.ts`・`TrackingService.java`）。

必要なもの：JDK 21（`brew install openjdk@21`）と Android SDK（`android/local.properties` の `sdk.dir` で場所を指定。このファイルはコミットしない）

```bash
export JAVA_HOME=/opt/homebrew/opt/openjdk@21/libexec/openjdk.jdk/Contents/Home
npm run android:build   # dist/ を取り込んで android/app/build/outputs/apk/debug/app-debug.apk を作る
adb install -r android/app/build/outputs/apk/debug/app-debug.apk
```

ずっと入れておくなら、リリース用の鍵で署名したリリース版（`npm run android:release`）がおすすめです。鍵の作り方は [docs/android.md](docs/android.md#リリース版を作る) にあります。
アプリの版は `package.json` の `version` から決まるので、更新のたびに上げてください。

家族などに配るときは APK ファイルを送り、受け取った端末で「提供元不明のアプリ」のインストールを許可してもらいます。
初回の記録開始時に「位置情報」と「通知」の許可を求めます。電池の最適化でアプリが止められる端末では、
設定でやまマップを「制限なし」にすると記録が途切れにくくなります。
記録中は画面を消しても、ほかのアプリを使っても、アプリを履歴からスワイプして消しても記録が続きます。
止めるのは「記録終了」か、通知の「停止」です（常駐アプリとしての今後の改善は [docs/android-plan.md](docs/android-plan.md)）。

Web版との違い、ビルド環境の準備、エミュレータ、デバッグ、署名とアップデートの注意は [docs/android.md](docs/android.md) にまとめています。
