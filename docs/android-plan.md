# 常駐アプリとしての改善計画（Android）

やまマップをスマホに入れたままにして、山に行くたびに記録する使い方に向けた改善の計画です。
目指すのは次の4つです。

- 記録が途切れない・点が欠けない
- 記録中の電池の減りが少ない
- 記録していないときは何もしない
- 更新や機種変更で記録を失わない

アプリ版の作りは [android.md](android.md)、コードの構成は [architecture.md](architecture.md) を見てください。

## 今の作りで、記録が続く場合・止まる場合

| 場面 | 記録 | 理由 |
|---|---|---|
| 画面を消す・ほかのアプリを使う・裏に回る | 続く | フォアグラウンドサービス（通知「やまマップで記録中」）が測位を続ける |
| 戻るボタン | 続く | アプリを終了せず、裏に回すだけ（`src/app/backButton.ts`） |
| 履歴からスワイプして消す | 続く | 記録のサービス（`TrackingService`）は画面と結び付けていない。点はサービスが端末に保存し、次に開いたときに取り込む |
| OS がメモリ不足で画面や WebView を止める | 続く | 同上 |
| 通知の「停止」 | 止まる | 次に開いたとき（開いていればすぐ）、そこまでで締める |
| メーカー独自の省電力機能 | 止まることがある | 電池の設定を「制限なし」にすると防げる |
| システムがサービスごと止める | 続くはず（未確認） | `START_STICKY` で再起動され、記録中だった記録を続ける。Android 12 以降は裏から始められず止まることがある |
| 端末の再起動 | 止まる | 次の起動で「続きを記録しますか」と聞く |

止まった記録は、次に起動したときに続きを記録できます。止まる前までの点は、端末に残っていれば取り込みます。

## 済ませたこと

### 2026-11-15（1回目）

- 戻るボタンでアプリを終了しない。メニュー → 地図の吹き出し → 下のシート → リプレイの順に閉じ、何もなければ裏に回す（`@capacitor/app`）
- 定期処理（30秒ごとの到着予想・毎秒の経過時間・毎分の空の色）を、画面が表のときだけ動かす（`src/app/scheduler.ts`）。Capacitor は裏でも JS のタイマーを止めないため
- 現在地の印と記録ボタンの、無限に続くアニメーションをやめた（表示中ずっと画面の合成が毎フレーム走っていた）
- リプレイ動画を小分けにして書き出す（全体を一度に base64 にすると、長い動画でメモリが足りなくなる）
- 自動バックアップから保存した地図を除いた（上限25MBを超えると、記録も含めてバックアップされなくなるため）
- リリース用の署名の準備（`android/keystore.properties`）と、`package.json` の version から versionCode を決める仕組み
- 圏外で標高が取れなかった点を、記録の終了時と記録を開いたときに標高タイルから埋める
- 記録が消されないよう、記録の開始時に保存領域の永続化を求める
- 点を端末に保存できなかったら覚えておいて、次の点と一緒に保存し直す。保存できていない間は上に警告を出す
- アプリ版の Service Worker は地図タイルだけを扱う（アプリ本体は APK に入っているので二重に持たない）

### 2026-11-15（2回目）：記録の点をネイティブ側で保存する

以前は `@capacitor-community/background-geolocation` が測位を JS に届け、JS が IndexedDB に保存していました。
このプラグインは画面（Activity）の終了と一緒に測位サービスを止め、WebView が止まると点も保存されないので、
履歴からスワイプしたときや OS に画面を止められたときに記録が途切れていました。これを次のように作り直しました。

- アプリの中に、位置情報タイプのフォアグラウンドサービス（`TrackingService.java`）を作った。`startForegroundService` で始め、画面とは結び付けない
- 測位は FusedLocationProviderClient で1秒間隔・5m 動いたときだけ、最大20秒ぶんまとめて受け取る。止まっていれば JS は起きない
- 受け取った測位は、サービスがその場で SQLite（`TrackingStore.java`）に保存する。気圧計があれば気圧も付ける
- WebView が動いていれば（裏でも）保存のたびに JS に知らせ、JS が取り込む（道迷いアラートが画面オフでも働くように）。
  WebView が止まっていた間の点は、表に出たとき・次に開いたときに取り込む
- 通知に経過時間・距離・「停止」ボタンを出す
- 記録中のままアプリを開いたら、裏で記録が続いていれば聞かずに続ける。通知の「停止」で止めていれば、そこまでで締める
- 古いプラグインを外した

エミュレータ（Android 16）で、履歴から消したあとも記録が続き、次に開いたときに点が取り込まれることを確かめた（[android.md](android.md#確かめたこと残っていること)）。

## これからの計画（優先度順）

### 1. 電池の最適化から外す案内

- 記録を始めるとき、アプリが電池の最適化の対象になっていたら理由を説明し、設定画面を開く
  （`isIgnoringBatteryOptimizations` → `ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`）。`TrackingPlugin` に足す
- APK を直接配るならこれで問題ない。Play ストアで配るなら、この画面を直接出すのは審査の対象になる。
  その場合は一覧の設定画面（`ACTION_IGNORE_BATTERY_OPTIMIZATION_SETTINGS`）へ案内する
- メーカー独自の省電力機能の外し方は機種ごとに違うので、[Don't kill my app!](https://dontkillmyapp.com/) を案内する

### 2. 画面を点けたまま記録するときの省電力表示（ポケット表示）

- 黒い背景に、経過時間・距離・次の地点と目的地の到着予想・日没だけを大きく出し、地図は描かない（地図の canvas を隠し、現在地の追従を外す）
- 有機ELの画面（Pixel 8a など）では、黒い部分はほとんど電気を使わない。地図の描画（特に 3D）も止まる
- Web 版は画面を点けたまま記録するしかないので、特に効く。タップすると地図に戻る

### 3. 記録の書き出しと引っ越し

- メニューに「すべての記録を書き出す」（1つの GPX に複数の記録）と、「GPX を記録として読み込む」を付ける
- 自動バックアップの除外が実機で効いているか確かめる（`adb shell bmgr backupnow io.github.ma38su.yamamap`）。
  WebView のデータの置き場所（`app_webview/Default/Service Worker/`）は WebView の版によって変わる可能性がある

### 4. 配布と更新

- リリース用の鍵を作り、パスワードと一緒に安全な場所に保管する（作り方は [android.md](android.md#リリース版を作る)）。
  **鍵をなくすと、同じアプリとして上書き更新できなくなる**
- 更新のたびに `package.json` の version を上げる（versionCode が上がる）
- R8 による縮小（`minifyEnabled`）は、プラグインの keep 設定を確かめる必要があるので今は使わない。APK を小さくしたくなったら試す
- 起動画面（スプラッシュ）の画像を用意する

### 5. 記録のサービスの仕上げ

- システムにサービスごと止められたあとの再起動（`START_STICKY`）を確かめる。Android 12 以降で裏から始められなかったときは、
  次にアプリを開いたときに「続きを記録しますか」と聞く（今もそうなるはず）
- 通知の許可を拒否された端末でも、記録が続き、「実行中のアプリ」から止められることを確かめる

## 実機で確かめること

- [ ] 画面を消したまま1時間以上（Doze に入る長さ）記録が続く
- [ ] ほかのアプリ（地図・カメラなど）を使っても記録が続く
- [ ] 履歴からスワイプして消しても記録が続き、開き直すと点が取り込まれる
- [ ] 戻るボタンで裏に回るだけになる（Android 11 以前の端末があれば、そこでも）
- [ ] 画面を消しているあいだも、道迷いアラートの通知が出る
- [ ] 電池の減り（1時間あたりの %）：画面オフで記録、画面オン（2D）、画面オン（3D）
- [ ] 圏外（機内モードと GPS）で記録して、終わったあとに標高が埋まる
- [ ] メーカーの省電力機能で止められない（電池の設定を「制限なし」にした場合・しない場合）
