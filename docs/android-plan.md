# 常駐アプリとしての改善計画（Android）

やまマップをスマホに入れたままにして、山に行くたびに記録する使い方に向けた改善の計画です。
目指すのは次の4つです。

- 記録が途切れない・点が欠けない
- 記録中の電池の減りが少ない
- 記録していないときは何もしない
- 更新や機種変更で記録を失わない

アプリ版の作りは [android.md](android.md)、コードの構成は [architecture.md](architecture.md) を見てください。

## 今の作りで、記録が続く場合・止まる場合

| 場面 | 記録 | 理由 |
|---|---|---|
| 画面を消す・ほかのアプリを使う・裏に回る | 続く | フォアグラウンドサービス（通知「やまマップで記録中」）が測位を続ける |
| 戻るボタン | 続く | アプリを終了せず、裏に回すだけにした（`src/app/backButton.ts`） |
| 履歴からスワイプして消す | **止まる** | プラグインが、画面（Activity）の終了と一緒に測位サービスを止める |
| OS がメモリ不足で画面や WebView を止める | **止まる・欠ける** | 点を保存しているのが WebView の JS なので、WebView が止まると点が保存されない |
| メーカー独自の省電力機能 | 止まることがある | 電池の設定を「制限なし」にすると防げる |
| 端末の再起動 | 止まる | 次の起動で「続きを記録しますか」と聞く |

止まった記録は、次に起動したときに続きを記録できます。止まっていた間の点は残りません。

## 済ませたこと（2026-11-15）

- 戻るボタンでアプリを終了しない。メニュー → 地図の吹き出し → 下のシート → リプレイの順に閉じ、何もなければ裏に回す（`@capacitor/app`）
- 測位プラグインのサービスを、ほかのアプリから使えないようにした（`AndroidManifest.xml` で `exported="false"`）
- 止まっているあいだは測位を JS に届けない（`distanceFilter: 5`）。休憩中や小屋に泊まっているあいだ、JS が毎秒起きなくなった
- 定期処理（30秒ごとの到着予想・毎秒の経過時間・毎分の空の色）を、画面が表のときだけ動かす（`src/app/scheduler.ts`）。Capacitor は裏でも JS のタイマーを止めないため
- 現在地の印と記録ボタンの、無限に続くアニメーションをやめた（表示中ずっと画面の合成が毎フレーム走っていた）
- リプレイ動画を小分けにして書き出す（全体を一度に base64 にすると、長い動画でメモリが足りなくなる）
- 自動バックアップから保存した地図を除いた（上限25MBを超えると、記録も含めてバックアップされなくなるため）
- リリース用の署名の準備（`android/keystore.properties`）と、`package.json` の version から versionCode を決める仕組み
- 圏外で標高が取れなかった点を、記録の終了時と記録を開いたときに標高タイルから埋める
- 記録が消されないよう、記録の開始時に保存領域の永続化を求める
- 点を端末に保存できなかったら覚えておいて、次の点と一緒に保存し直す。保存できていない間は上に警告を出す
- アプリ版の Service Worker は地図タイルだけを扱う（アプリ本体は APK に入っているので二重に持たない）

## これからの計画（優先度順）

### 1. 記録の点をネイティブ側で保存する（最優先）

**問題**：点を保存しているのは WebView の JS です。そのうえプラグイン（`@capacitor-community/background-geolocation`）は、
`handleOnDestroy` と `onUnbind` で測位サービスを止めます。そのため、履歴からスワイプしたときや、OS が画面・WebView を止めたときに記録が途切れ、点が欠けます。

**作り**：

- アプリの中（`android/app`）に、自前の小さな Capacitor プラグインと、位置情報タイプのフォアグラウンドサービスを作る。
  サービスは `startForegroundService` で起動し、画面（Activity）とは結び付けない。`onTaskRemoved` でも止めない
- 測位は `FusedLocationProviderClient` を使う。間隔は1〜2秒、最小移動距離は5m にする。
  画面を消している間は `setMaxUpdateDelayMillis`（30〜60秒）でまとめて受け取り、CPU を眠らせる。プラグインの「1秒間隔で毎回届く」より電池が持つ
- 受け取った点は、サービスがその場で端末に保存する（SQLite か追記ファイル）。WebView が止まっていても欠けない
- JS 側（`src/track/location.ts`・`recorder.ts`）は「開始・停止」と「ある時刻以降の点を取り出す」だけにする。
  表に出たときと起動時にたまった点を取り込み、今と同じフィルタ（誤差40m超を捨てる、8m以上動いたときだけ、速度の飛びを捨てる）をかけてから、
  標高を付けて IndexedDB に入れる。取り込んだ点はネイティブ側から消す
- 通知に経過時間と距離を出し、「停止」ボタンを付ける
- 許可を1つずつ求める流れ（`requestTrackingPermissions`）と、Web 版の動きは変えない

**確かめ方**：エミュレータで記録中に、次の3つを試して点が欠けないことを確かめる。

- 履歴からスワイプする
- `adb shell am kill io.github.ma38su.yamamap` でアプリを止める
- `adb shell dumpsys deviceidle force-idle` で Doze に入れる

**作業量**：中〜大（Java 300〜500行、JS 100行ほど）。終わったら古いプラグインは外す。

### 2. 電池の最適化から外す案内

- 記録を始めるとき、アプリが電池の最適化の対象になっていたら理由を説明し、設定画面を開く
  （`isIgnoringBatteryOptimizations` → `ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`）。1 のネイティブプラグインに入れる
- APK を直接配るならこれで問題ない。Play ストアで配るなら、この画面を直接出すのは審査の対象になる。
  その場合は一覧の設定画面（`ACTION_IGNORE_BATTERY_OPTIMIZATION_SETTINGS`）へ案内する
- メーカー独自の省電力機能の外し方は機種ごとに違うので、[Don't kill my app!](https://dontkillmyapp.com/) を案内する

### 3. 画面を点けたまま記録するときの省電力表示（ポケット表示）

- 黒い背景に、経過時間・距離・次の地点と目的地の到着予想・日没だけを大きく出し、地図は描かない（地図の canvas を隠し、現在地の追従を外す）
- 有機ELの画面（Pixel 8a など）では、黒い部分はほとんど電気を使わない。地図の描画（特に 3D）も止まる
- Web 版は画面を点けたまま記録するしかないので、特に効く。タップすると地図に戻る

### 4. 記録の書き出しと引っ越し

- メニューに「すべての記録を書き出す」（1つの GPX に複数の記録）と、「GPX を記録として読み込む」を付ける
- 今回入れた自動バックアップの除外が実機で効いているか確かめる（`adb shell bmgr backupnow io.github.ma38su.yamamap`）。
  WebView のデータの置き場所（`app_webview/Default/Service Worker/`）は WebView の版によって変わる可能性がある

### 5. 配布と更新

- リリース用の鍵を作り、パスワードと一緒に安全な場所に保管する（作り方は [android.md](android.md#署名とバージョン)）。
  **鍵をなくすと、同じアプリとして上書き更新できなくなる**
- 更新のたびに `package.json` の version を上げる（versionCode が上がる）
- R8 による縮小（`minifyEnabled`）は、プラグインの keep 設定を確かめる必要があるので今は使わない。APK を小さくしたくなったら試す
- 起動画面（スプラッシュ）の画像を用意する

### 参考：プラグインに手を入れる案（採らない）

`patch-package` でプラグインの `handleOnDestroy` と測位の間隔を書き換える方法もあります。
ただし点の保存先が WebView のままなので、WebView が止まると点が欠ける問題は残ります。1 のほうを勧めます。

## 実機で確かめること

- [ ] 画面を消したまま1時間以上（Doze に入る長さ）記録が続く
- [ ] ほかのアプリ（地図・カメラなど）を使っても記録が続く
- [ ] 戻るボタンで裏に回るだけになる（Android 11 以前の端末があれば、そこでも）
- [ ] 電池の減り（1時間あたりの %）：画面オフで記録、画面オン（2D）、画面オン（3D）
- [ ] 圏外（機内モードと GPS）で記録して、終わったあとに標高が埋まる
- [ ] メーカーの省電力機能で止められない（電池の設定を「制限なし」にした場合・しない場合）
